FLOW Design System v2
リキッド・タブ — 動きの仕様
面はフラットな白のまま、動きとタブ周りだけを液体的にする。ガラスは「上に浮いているもの」にしか使わない。密度の高い数字が読めなくなるため。
01 — インジケータは位置だけでなく幅も追従する
ここが「液体的」の本体。四角が瞬間移動するのではなく、伸びながら移動して縮む。framer-motion の layoutId を当てるだけで得られる（幅が違う要素間で自動的に補間される）。

既存の落とし穴: 現行 TabSwitch.tsx:21 は layoutId="activeTab" というグローバルな固定文字列を使っている。2つ同時にマウントすると互いのインジケータを奪い合う。新しい LiquidTabs はインスタンスごとのIDを必須引数にする。
02 — スプリングは3つだけ。springs.ts に固定する
現行はスプリング値が8箇所にバラバラに直書きされている（300/30・400/28・400/30・400/22・300/28・60/18/1.2…）。用途ごとに3つへ集約し、各所ではマジックナンバーを書かない。
名前使う場所値ねらい
indicator タブ／セグメントの選択表示 stiffness 380 / damping 32 跳ねずに素早く。追従が遅いと「重い」と感じる
morph TOPの入口 → 詳細パネルの展開 stiffness 260 / damping 30 面が大きいので少しゆっくり。速いと形が追えない
enter 一覧・カードの出現 180ms / cubic-bezier(.2,0,0,1) 出現はスプリングにしない。件数が多いと画面が騒がしくなる
03 — ガラスを使ってよい場所
TOP の入口カードと指示入力
ガバナンスのタブ
成果物のフォルダタブ
チャットの部署チップ
スマホのボトムナビ
カード・表・サイドバー・モーダル本体
ガバナンスのログ表のように数字が密なところで透過させると、背景の帯が数字に重なって読めなくなる。前回この理由でガラスを全廃した。
04 — 動きを止める条件（両方とも必須）
視差効果を減らす設定が ON のとき
useReducedMotion() が true ならスプリングを切って即時切替にする。現状これを尊重しているのは BottomNav と FooterSearch の2ファイルだけ。index.css の prefers-reduced-motion は CSS アニメーションしか止めず、framer-motion の transform は止まらない。
backdrop-filter が効かない環境
@supports not (backdrop-filter: blur(1px)) で不透明な白に落とす。フォールバックを書かないと、透けない環境で半透明の白がそのまま出て文字が背景に溶ける。

05 — 統合する対象
実地調査の結果、排他選択のUIはアプリ内に約14箇所あるが、動いているのは2つだけ（TabSwitch と BottomNav）。残り12箇所はプレーンな <button> のクラス差し替えで、ガバナンスのタブ・成果物のフォルダタブ・チャットの部署ピッカー・タスクの絞り込み・エージェント作成モーダルの3つの選択群などが該当する。
これらを LiquidTabs 1本に寄せる。副産物として、TabSwitch.tsx が bg-gray-100 / #2D2D2D 直書きで今もダークモードで壊れている問題も消える。
壊すものが無い: Tailwind の独自キーフレーム6本（aurora×3・shimmer・float・pulse-glow）、backdropBlur の4キー、duration-slow/dramatic・ease-emphasized/smooth はいずれも参照ゼロ。さらに .liquid-*-shell は中身が空のスタブなのに JSX からは参照され続けている＝CSSだけで液体表現を戻せる。
キーボード操作は role="tablist" ／ aria-selected ／ 左右矢印キーでの移動を実装する。インジケータの移動はあくまで見た目で、フォーカスの所在は独立して分かるようにする（focus-visible の2pxリング）。
